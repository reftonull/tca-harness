# Harness validation

This macOS XcodeGen project tests the three-layer harness without launching a GUI app. It consumes the root package directly and uses its own build directory. No isowords checkout or private TCA 2 access is needed. Prepare it with:

```
xcodegen generate --spec prototypes/harness-validation/project.yml
cd prototypes/harness-validation
flowdeck test --config flowdeck.json
```

There are 24 tests: six macro snapshots/diagnostic cases and eighteen real TCA runtime/attachment tests. Coverage includes optional, identified and stack scopes; nested structs, scalar enums, arrays and null inputs; typed argument rejection; state projection exclusions/redaction; same-route replacement; duplicate route rejection; request deduplication; explicit completion/cancellation; cancellation of receipts when a child disappears; and timeline sources, value-matched effect causes, effect status, mounts, privacy detail, deferred snapshots and paging.

The runtime fixture's State intentionally contains NSObject and does not conform to Codable. Its generated descriptors compose into a real TCA Store; no fake dispatcher is substituted. Async completion is tested by injecting the reducer's response action, keeping timing deterministic.

SwiftSyntax's C shim include path is explicit because the macro implementation is compiled as a normal Xcode library for MacroTesting, in addition to the actual package compiler plugin. Tests are also declared in the root Package.swift. Macro snapshots are generated by MacroTesting and asserted on subsequent runs.
